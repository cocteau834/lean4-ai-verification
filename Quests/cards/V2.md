## 🎓 V2 · Vericoding: The spec is the product

**What you practiced.** Treating an AI-written code + spec + proof as a pull request to review: breaking a weak spec with a wrong implementation, writing a stronger spec, testing it in both directions (rejects the wrong code, accepts the right code), and proving how much your spec pins down.

**On the job.** In verified code generation, the proof is checked by a machine, so the human's work is the spec. Verification engineers write and review specs for real code (in Lean, Dafny, Verus and other tools), and AI teams building vericoding systems need people who can tell a strong spec from a weak one. "Say what, not how" and "test the spec, not just the code" are habits those teams look for.

**Level up.** Write a full spec for sorting (sorted AND a permutation of the input), then prove that Lean's `List.mergeSort` meets it. Use `exact?` to find the library lemmas.

**Résumé line.** “Reviewed and strengthened specifications for AI-generated code in Lean 4; demonstrated spec loopholes with counter-implementations and proved implementations against corrected specs.”
